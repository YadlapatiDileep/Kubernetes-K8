4)Core Architecture of a Cluster

A Kubernetes cluster consists of two main parts: the Control Plane (the brain) and Worker Nodes (the muscle).

1. The Control Plane (Master Node)

The control plane makes global decisions about the cluster (e.g., scheduling), detecting and responding to cluster events. Its key components include:

API Server: The front end of the control plane; all administrative commands and internal communications go through here.

etcd: A consistent and highly available key-value store used as Kubernetes' backing store for all cluster data.

Scheduler: Watches for newly created Pods with no assigned node and selects a node for them to run on.

Controller Manager: Runs controller processes that regulate the state of the cluster, 3 types

a. replication controller: ensuring the correct number of pods are running, if not it will create
b. node controller: if any server crash or delete it will automatically create server
c. service controller: if any service crash or delete it will automatically create service

2. Worker Nodes

Worker nodes are the machines (physical servers or virtual machines) that actually run your applications. Their components include:

Kubelet: An agent that runs on each node to ensure containers are running inside a Pod.

Kube-proxy: A network proxy that maintains network rules on nodes, enabling network communication to your Pods from inside or outside the cluster.

Container Runtime: The software responsible for running containers (e.g., containerd, CRI-O).
